# Contributing to anmacgamer

[简体中文](CONTRIBUTING.md) · English

Thank you for helping! This guide covers reporting problems, setting up a macOS development environment, building and testing, and the conventions to follow before you send code.

## Reporting problems and ideas

- Search the [Issues](https://github.com/wyb-070110/anmacgammer/issues) first.
- Use the bug report template: give the version, the macOS version and Mac chip (Apple silicon or Intel), the phone model and Android version, the connection and the steps to reproduce, and attach the file made by "Settings > About > Export diagnostics".
- Do not open public issues for security problems; report them privately as described in [SECURITY.md](SECURITY.md).

## Sending changes

1. Fork the repository and branch off `main`.
2. Keep changes small and complete: one pull request does one thing and comes with its tests.
3. Build and run the relevant tests locally (see below); QML lint stays at zero warnings.
4. Write commit messages in English, with a first line of up to 72 characters that says what changed, and the reasons after a blank line when needed.
5. Open a pull request and fill in the template: what changed and how you verified it.

For larger changes (new features, protocol or profile format changes), open an issue to discuss them first.

## Repository layout

| Path | Contents |
|:--|:--|
| `src/` | The macOS app in C++20 / Objective-C++20 with Qt 6 / Qt Quick (Metal), and the `gs` command line (`src/cli`); modules are described in [docs/architecture.md](docs/architecture.md) |
| `android/` | Phone side: `protocol`, `server` (plain Java) and `companion` (the companion app, Kotlin) |
| `protocol/` | The protocol specification `SPEC.md` and the golden test vectors shared by both sides |
| `sdk/` | Script API types and documentation generated by `gs api write`, and the C header for native extensions |
| `tests/` | Unit, integration and interface tests, and test data |
| `examples/` | Sample components, tasks and extensions |
| `tools/` | Development and release scripts: `build_macos_deps.sh`, source rules, frame and touch trace analysers, generators |
| `packaging/macos/` | Self-contained `.dmg` packaging, Icon Composer scripts and release notes |
| `third_party/` | Third-party dependencies kept in the repository, listed in [third_party/README.md](third_party/README.md) |

## Development environment

| Tool | Version |
|:--|:--|
| Operating system | macOS 14 Sonoma or later (Apple silicon or Intel) |
| Xcode / Command Line Tools | Xcode 16+ (recompiling `.icon` Liquid Glass assets requires Xcode 26+) |
| Qt | 6.10.3 for macOS (with Qt Quick, Qt Quick Controls 2, Qt Shader Tools and Qt Test) |
| CMake & Ninja | CMake 3.28 or later, with Ninja |
| Local libraries | `brew install cmake ninja openssl@3 ffmpeg sdl3 libusb android-platform-tools` |
| Python | 3.10 or later |
| JDK & Android SDK (optional) | JDK 17, Android SDK platforms 35 / 36 (only needed when changing `android/`) |

Configuring never goes online; please do not add network downloads such as `FetchContent`.

## Building the macOS app

Qt is picked up from `~/Qt/6.10.3/macos` by default (pass `-DCMAKE_PREFIX_PATH=<path>` if installed elsewhere):

```bash
cmake --preset mac-app
cmake --build --preset mac-app
ctest --preset mac-app
```

Available macOS / POSIX presets:

| Preset | Purpose |
|:--|:--|
| `posix-core` | Builds and tests only the Qt-free core libraries (Debug) |
| `posix-core-release` | Optimised build and benchmarks for the core libraries |
| `mac-app` | Full local development build (`GameScrcpy.app`, `gs` and test programs) |
| `mac-release` | Universal (`arm64` + `x86_64`) release build targeting macOS 14+, linking the self-built LGPL libraries from `tools/build_macos_deps.sh` |

Outputs go to `build/<preset>/bin`: `GameScrcpy.app`, `gs`, `gs-scripthost`, `gs-exthost` and the test programs.

## Building the Android side

Point `ANDROID_HOME` at the Android SDK, then:

```bash
cd android
./gradlew build
```

`./gradlew build` compiles the `protocol`, `server` and `companion` modules and runs JUnit and lint (lint warnings are errors). The server stays plain Java, without Kotlin. Dependency versions live in `android/gradle/libs.versions.toml`.

## Testing

- Each module has a doctest program (`gs_base_tests`, `gs_protocol_tests`, `gs_input_tests`, `gs_session_tests`, `gs_media_tests`, `gs_script_tests`, `gs_platform_tests`, `gs_hardware_tests`, `gs_render_tests` and more), run through CTest: `ctest --preset mac-app`, or `-R <regex>` for a subset.
- QML lint must report zero warnings: `cmake --build --preset mac-app --target all_qmllint`.
- The protocol tests read every golden vector in `protocol/vectors/`; C++ and Java must both match byte for byte.
- Tests that need a phone (`gs_adb_device_tests`, `gs_session_device_tests`) run only when `GS_ADB_TEST_SERIAL` names a device and are skipped otherwise.
- The mirror window works without a phone: `./build/mac-app/bin/GameScrcpy.app/Contents/MacOS/GameScrcpy --demo-device tests/data/video/emulator_h265.media` adds a demo device that loops a recorded picture; set `GS_DATA_DIR` to isolate settings and data during testing.

## Changing the protocol

1. Change `protocol/SPEC.md`.
2. Change `protocol/tools/gen_vectors.py` and run `python3 protocol/tools/gen_vectors.py` to regenerate the vectors.
3. Make the tests pass on both the C++ side (`src/protocol`) and the Java side (`android/protocol`).

Never edit the generated vectors by hand.

## Changing the script API

After changing the API table in `src/script/src/Api.cpp`, run `./build/mac-app/bin/gs api write sdk` from the repository root to regenerate `sdk/`.

## Interface text and translations

- Interface text is written in English in the code (`tr()` / `qsTr()`); Chinese lives only in `src/app/i18n/gamescrcpy_zh_CN.ts`.
- After adding or changing interface text, run the translation update target (`GameScrcpy_lupdate`) and fill in the Chinese entries. Every entry must be translated.
- The built-in help lives in `src/app/help/`: `index.json` gives the order, names, icons and titles of the articles, with one Markdown file each under `en/` and `zh_CN/`; new articles go into the resource list in `src/app/CMakeLists.txt`.

## Source rules

`python3 tools/check_source_rules.py` checks that:

- Product code never runs or parses human-readable command output such as `dumpsys` or `wm` (R5).
- Nothing synchronizes with fixed delays: no sleeps, no single-shot timers with a delay, no `postDelayed` (R9). Where the delay is the feature itself, the line carries `source-rule-allow R9: <reason>`.
- Every user-facing string has its translation, and source strings are English.
- Controls in `src/ui/controls` take colors, sizes and durations only from the theme.
- Every QML `Text` declares its `textFormat`.

## Code conventions

- C++20 / Objective-C++20, formatted by `.clang-format` and `.editorconfig`; identifiers and commit messages in English.
- Let the code speak for itself: the code base carries almost no inline comments, apart from a short description at the top of a file; explanations belong in the pull request or the documentation. The `source-rule-allow` marker above is the only note that must sit on the line.
- Interface colors, type sizes, spacing, corner radii and motion come from the theme module `src/ui/theme`, never as bare numbers.
- New features come with tests; a bug fix starts with a test that fails.

## Packaging a release

1. Build the universal macOS 14+ dependencies (LGPL FFmpeg, dav1d, SDL3, OpenSSL, libusb) with `tools/build_macos_deps.sh`.
2. Build the `mac-release` preset to produce the universal app bundle.
3. Run `packaging/macos/package.sh` to bundle Qt frameworks, dylibs, `adb` and code signatures into a self-contained `.dmg`.
4. After changing icon layers or metadata under `packaging/macos/icon/`, run `packaging/macos/icon/build_icon.sh` (requires Xcode 26+) to refresh `Assets.car` and `.icns`.
